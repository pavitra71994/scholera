# School Management API

Spring Boot REST API for a single-school management system. It provides session-based authentication, role-aware access, school and academic administration endpoints, and Flyway database migrations.

## Requirements

- Java 21 or newer.
- Maven 3.9+ (or use the included `./mvnw` wrapper).
- PostgreSQL only if using the persistent PostgreSQL profile; local H2 requires no separate database service.

## Run locally with H2

The default profile uses an in-memory H2 database in PostgreSQL compatibility mode. Configure a bootstrap administrator before starting the app:

```sh
export APP_BOOTSTRAP_ADMIN_USERNAME=admin
export APP_BOOTSTRAP_ADMIN_PASSWORD='choose-a-local-password-at-least-12-characters'
./mvnw spring-boot:run
```

The app listens on port `8080` by default. Configure `SERVER_PORT` to use a different port. The bootstrap operation inserts the admin only if the username does not already exist; it does not reset an existing account's password. H2 is in-memory, so its application data is lost when the API process stops.

## Run with PostgreSQL

Set a local database password, start the included PostgreSQL service, and run the API with the `postgres` profile:

```sh
export DATABASE_PASSWORD='choose-a-local-database-password'
docker compose up -d postgres

export APP_BOOTSTRAP_ADMIN_USERNAME=admin
export APP_BOOTSTRAP_ADMIN_PASSWORD='choose-a-local-password-at-least-12-characters'
./mvnw spring-boot:run -Dspring-boot.run.profiles=postgres
```

The compose service creates database `school_management` and user `school_management`, and stores data in a Docker volume. Set `DATABASE_URL`, `DATABASE_USER`, or `DATABASE_PASSWORD` to override the profile defaults. Never commit local secrets or use development passwords in production.

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `SERVER_PORT` | `8080` | HTTP port |
| `FRONTEND_ORIGIN` | `http://localhost:5173` | Allowed credentialed CORS origin |
| `APP_BOOTSTRAP_ADMIN_USERNAME` | empty | Optional initial administrator username |
| `APP_BOOTSTRAP_ADMIN_PASSWORD` | empty | Optional initial administrator password; minimum 12 characters |
| `DATABASE_URL` | `jdbc:postgresql://localhost:5432/school_management` | PostgreSQL JDBC URL in the `postgres` profile |
| `DATABASE_USER` | `school_management` | PostgreSQL username in the `postgres` profile |
| `DATABASE_PASSWORD` | empty | PostgreSQL password in the `postgres` profile and compose |

Both bootstrap admin variables must be set together or both left empty. The UI origin must match `FRONTEND_ORIGIN` when the UI is hosted somewhere other than the default.

## API reference

All routes use the `/api/v1` base path. Except for health and CSRF-token retrieval, endpoints require an authenticated session. School data writes and all people, attendance, and exam endpoints are administrator-only. JSON examples below show request/response shapes; IDs are generated by the API.

### Health and authentication

| Method | Path | Access | Purpose |
|---|---|---|---|
| `GET` | `/health` | Public | Returns API status, for example `{"status":"UP"}` |
| `GET` | `/auth/csrf` | Public | Returns `token` and `headerName` for subsequent writes |
| `POST` | `/auth/login` | Public + CSRF | Authenticates and creates a session |
| `GET` | `/auth/me` | Authenticated | Returns the signed-in `username` and `role` |
| `POST` | `/auth/logout` | Authenticated + CSRF | Invalidates the current session; returns `204` |

Login request:

```json
{"username":"admin","password":"your-local-password"}
```

Successful login response:

```json
{"username":"admin","role":"ADMIN"}
```

The UI keeps the session cookie by sending credentialed requests. For manual API use, retain the cookie returned at login. For state-changing requests, first call `/auth/csrf` and send the returned token in the header named by `headerName`. The API does not provide public registration.

### School profile

| Method | Path | Access | Purpose |
|---|---|---|---|
| `GET` | `/school` | Authenticated | Read school name and timezone |
| `PATCH` | `/school` | Admin | Update school name and IANA timezone |

```json
{"name":"North School","timezone":"Asia/Kolkata"}
```

### Classes and sections

| Method | Path | Access | Purpose |
|---|---|---|---|
| `GET` | `/classes` | Authenticated | List classes and nested sections |
| `POST` | `/classes` | Admin | Create a class |
| `POST` | `/classes/{classId}/sections` | Admin | Add a section to a class |
| `DELETE` | `/classes/{classId}/sections/{sectionId}` | Admin | Remove a section; returns `204` |

Create requests:

```json
{"name":"Grade 1"}
```

```json
{"name":"Section A"}
```

Class names are unique without regard to case. Section names are unique within their class, without regard to case. The list response contains class `id`, `name`, and a `sections` array with section `id` and `name`.

### Students and teachers

| Method | Path | Access | Purpose |
|---|---|---|---|
| `GET` | `/people?role=STUDENT` | Admin | List students |
| `GET` | `/people?role=TEACHER` | Admin | List teachers |
| `POST` | `/people` | Admin | Create a student or teacher account |

Student request:

```json
{
  "fullName":"Jordan Lee",
  "username":"jordan.lee",
  "password":"initial-password-at-least-12",
  "role":"STUDENT",
  "sectionId":1
}
```

Teacher request:

```json
{
  "fullName":"Taylor Morgan",
  "username":"taylor.morgan",
  "password":"initial-password-at-least-12",
  "role":"TEACHER",
  "sectionId":null
}
```

Passwords must be at least 12 characters. Usernames must be unique, and only `STUDENT` and `TEACHER` roles can be created through this endpoint. A student must be assigned to an existing section; a teacher has no student section assignment. The response includes the person's ID, full name, username, role, and (for students) section and class details.

### Attendance

| Method | Path | Access | Purpose |
|---|---|---|---|
| `GET` | `/attendance?sectionId={id}&date=YYYY-MM-DD` | Admin | List students for the section with any saved status for the date |
| `POST` | `/attendance` | Admin | Save or update the complete section register for a date |

```json
{
  "sectionId":1,
  "date":"2026-10-25",
  "records":[
    {"studentId":4,"status":"PRESENT"},
    {"studentId":5,"status":"LATE"},
    {"studentId":6,"status":"ABSENT"}
  ]
}
```

Each student can have one status per date: `PRESENT`, `ABSENT`, or `LATE`. Submit one record for every student currently assigned to the selected section, without duplicates. GET returns students even when there is no saved record yet; their `status` is `null` until attendance is recorded.

### Exams and marks

| Method | Path | Access | Purpose |
|---|---|---|---|
| `GET` | `/exams?sectionId={id}` | Admin | List exams for a section, including saved marks |
| `POST` | `/exams` | Admin | Create an exam for a section and subject |
| `POST` | `/exams/{examId}/marks` | Admin | Save or update marks for the exam's section |

Create exam:

```json
{
  "sectionId":1,
  "name":"Term 1",
  "subject":"Mathematics",
  "maximumMarks":100
}
```

Save marks:

```json
{
  "marks":[
    {"studentId":4,"obtainedMarks":92.5},
    {"studentId":5,"obtainedMarks":81}
  ]
}
```

Marks use decimal numbers with up to two places. The maximum must be greater than zero; scores must be zero or greater and may not exceed the exam maximum. Submit one score for every student in the exam's section.

### Error responses

Validation and request errors are returned as JSON with a `message` field. Typical status codes include `400` for invalid input, `401` for unauthenticated requests, `403` for a role without access, `404` for a missing resource, and `409` for duplicate names or usernames where detected.

## Database and migrations

Flyway applies the SQL migrations in `src/main/resources/db/migration` at startup. Hibernate validates the schema; it does not generate production tables. Keep schema changes in a new migration rather than editing an already-applied migration. Current migrations establish users and school profile, classes and sections, and people, attendance, exams, and marks.

## Tests

```sh
./mvnw test
```

The integration test suite uses an isolated in-memory H2 database and MockMvc to exercise authentication, role restrictions, school settings, class/section management, accounts, attendance, and exam marks.
